# 技术适配声明

> 依据：`docs/PRD/PRD.md`、`docs/项目状态.md` 决策台账（D1–D11）、通用手册第一部分（一至六节）。
> 手册对账：已读通用手册第一部分，与 AGENTS.md 十条底线和是否表对账，**无冲突**。
> 日期：2026-11-04

## 1. 产品形态判断
- 产品类型与核心任务：面向英语老师的跟读作业助手。老师填教学目标 → 生成跟读作业和课件大纲；孩子跟读 → AI 评测、分流、反馈、加练；老师只复核 AI 拿不准的录音。
- 核心交互：分阶段确认（老师确认后才发布作业；AI 分流后，拿不准的交老师判定）。
- 开发路径：**后端先行**。最大的不确定性在模型效果：儿童录音的评测准确率、反馈和加练文案是否合适、分流是否靠谱。这些先用接口和测试验证，界面等核心链路成立后再做。
- 验收界面：**临时验收界面**。阶段 2 放一个简单网页（填教学目标、上传录音、看结果、听音频），只为验收用，阶段 3 开始时废弃，不做手机适配。
- 上线套餐：腾讯云开发免费体验版（台账 D9）。
- 当前阶段范围：阶段 1 只出本声明，不写代码。

## 2. 采用的默认方案
- Python 3.12 + FastAPI + Pydantic + pytest：手册默认后端组合，与上线镜像一致。
- Git：已有仓库（工具包本身），密钥检查依赖它。
- 模型调用用官方 SDK：大模型用 DeepSeek（兼容 OpenAI 的接口），口语评测和语音合成用腾讯云官方 Python SDK。
- 错误统一返回 `{"error": {"code", "message"}}`，接口前缀 `/api/v1`。

## 3. 触发的按需模块
- SQLite + SQLAlchemy + Alembic：老师、班级、学生、作业、录音、评测结果、老师判定之间是多实体关系，还要按班级统计。**阶段 2-1 引入**；每张业务表从第一张起带老师归属字段（D5）。
- 本地文件目录存音频：孩子录音和示范音频是二进制文件，不放进数据库。**阶段 2-1 引入**（示范音频），2-2 起存孩子录音。
- 音频格式转换（ffmpeg）：浏览器录音一般是 webm 格式，口语评测接口要求的格式需在 2-2 实测确认，不符合就转码。**阶段 2-2 按需引入**。
- 到期清理：孩子录音 30 天后自动删除（D6）。MVP 做成"服务启动时 + 可手动调用"的清理接口，上线后再接平台定时触发。**阶段 2-3 引入**。
- 审计记录：每次模型调用、AI 分流结果、老师推翻 AI 的判定都记一行，用来校准和排查。**阶段 2-1 起引入**。
- 流程编排：分流规则（读得好 / 有明确问题 / 交老师）和加练上限（2 轮）写在代码里，不交给模型临场决定。
- 不引入：知识库检索（Chroma）、任务队列、SSE 流式输出、对象存储、Word/PDF 处理。生成一份作业在 30 秒内，同步请求加超时即可。

## 4. 偏离或暂缓的默认方案
- **开发运行环境（D12 已定，见第 6 节）**：工具包按"在你的 Mac 上开发"设计。现在这个云端工作区**访问不了 DeepSeek 和腾讯云的接口**（已实测：两边的请求都被网络限制挡住），也不能让你在手机上打开页面。不解决的话，阶段 2 无法做真实模型验证，阶段 3 无法用手机走查，阶段 4 无法部署。
- Python 版本：云端工作区是 3.13，与默认 3.12 不同；无论在哪个环境开发，都用 3.12 建虚拟环境，部署前在 3.12 下跑通测试。
- 孩子端从微信小程序改为手机网页（D10）。影响：家长要在微信里点链接打开，不是小程序入口。以后若要做小程序，复用同一套后端。
- 课件"上传历史课件学风格"、输出 PPT 文件暂缓（D11）。影响：第一版课件只有可编辑的文字大纲。重新评估条件：跟读闭环验收通过、老师试用后仍认为需要。
- 定时清理暂用"启动时 + 手动接口"代替平台定时任务。重新评估条件：阶段 4 上线时接云托管定时触发。

## 5. 强制底线检查
- 密钥与隐私：计划通过。Key 只放 `backend/.env`（已在 .gitignore 中），线上用平台环境变量；孩子录音、孩子姓名不进日志（D7）；录音 30 天删除（D6）。
- 数据与任务可恢复：计划通过。所有业务数据进 SQLite，音频进本地文件目录；按手册写重启检查钩子，由 verify.sh 实测。
- 输入输出校验：计划通过。接口用 Pydantic 定义请求和响应；大模型输出（作业、反馈、加练）做结构校验，不合格重试有限次，仍失败返回明确错误；录音校验格式、真实类型、时长不超过 30 秒、大小不超过 2 MB。
- 错误与日志边界：计划通过。统一错误结构，不返回堆栈；模型调用有超时、失败处理和有限重试，含 SDK 初始化失败的兜底。
- 测试与真实模型验收：每个子阶段先跑 mock 自动化测试（不少于 5 条，覆盖错误路径），再用真实 Key 跑冒烟脚本，脚本自动写冒烟记录；第一次真实冒烟时请你给 5–10 条样例打分，据此定 D2 的标准。

## 6. 需要产品经理决定的问题

无待定项。

- D12 开发与运行环境（2026-11-04 已定）：产品经理决定**暂时继续在云端工作区开发**，环境问题往后推；需要接真实模型时，由 AI 提前告诉产品经理，届时他去申请 Key，同时解决网络访问（再定是换到 Mac 还是给云端开放网络）。终端只做 Web（老师端网页 + 孩子端手机网页），与 D10 一致。
- 由此带来的影响（如实说明）：阶段 2 每个子阶段可以先写代码、跑 mock 测试、交证据包给你看进度，但按工具包规则，真实模型冒烟没跑之前，是否表第 3 项只能填"待验"，子阶段不能宣布完成、不能翻页。所以最晚在阶段 2-1 验收前，要把 Key 和网络准备好。

## 附：费用估算（开发验收期）
- DeepSeek 大模型：官网价格为每百万 tokens 输入约 1 元、输出约 2 元。生成一份作业加若干条反馈约几千 tokens，开发验收期预计不到 5 元。
- 腾讯云口语评测：按调用次数计费，有预付费套餐包（较早资料显示约 9.9 元 1 万次）；开发验收期预计几百次，费用很小。
- 腾讯云语音合成：按合成字符数计费，示范音频生成一次后缓存复用，用量很小。
- 合计预计远低于台账 D4 的每月 50 元上限。口语评测和语音合成的准确单价，阶段 2 开通前在腾讯云控制台核实后再报给你，开通前会先问你。
